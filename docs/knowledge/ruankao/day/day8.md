# 第 8 天：资源管理与团队管理

## 一、今天的目标

第 8 天进入信息系统项目管理师里最容易出现“道理都懂，但案例一写就变成空话”的模块之一：资源管理与团队管理。

这一模块的特点很明确：

- 综合知识会考资源管理主线、角色职责、责任分配矩阵、冲突管理、激励理论、资源平衡与资源平滑等高频概念。
- 案例分析里经常把人员短缺、职责不清、跨部门协作困难、供应商配合差、资源冲突、团队士气下降混在一起，最后看你能不能从机制、职责、沟通、激励四个维度写出措施。
- 论文不会要求你大量背术语，但非常看重你能不能把“资源规划、职责分工、团队建设、冲突解决、资源协调、资源监控”写成完整的项目管理动作链。

完成今天后，你至少要达到以下状态：

- 能说清资源管理主线，从资源规划到获取资源、建设团队、管理团队、控制资源是怎么串起来的。
- 能区分人力资源、实物资源、角色、职责、资源日历、责任分配矩阵等概念。
- 能区分资源平衡与资源平滑，理解二者的适用条件和影响。
- 能识别团队冲突题中的常见根因，并从职责、机制、沟通和激励四个维度作答。
- 能基于 day1 的主项目背景，写出一版“资源管理”或“团队管理”论文提纲。

今天的最低交付物有 4 项：

## 三、今天必须先了解的信息

### 1. 为什么资源管理和团队管理是“隐性失控源”

很多项目不是输在技术方案不行，而是输在下面这些问题：

- 关键岗位没人或人不够
- 职责边界不清，出了问题互相推责
- 多项目并行导致资源冲突
- 团队内部关系紧张，效率下降
- 外部供应商和内部团队协同差
- 项目经理只会催进度，不会做资源协调和团队建设

所以 day8 的本质不是只记几个理论，而是要答清楚一个问题：

**项目任务有人做、做得动、愿意做、能协同、遇到冲突还能被机制化解决。**

### 2. 今天要重点解决的 5 个问题

1. 资源管理主线到底包括哪些环节。
2. 角色、职责、权限和责任边界怎样明确。
3. 资源冲突、团队冲突、跨部门协作问题如何识别和处理。
4. 资源平衡和资源平滑分别解决什么问题。
5. 激励、授权、考核、团队建设如何真正作用于项目执行。

### 3. 今天和前几天的关系

- day4 回答项目做什么。
- day5 回答这些工作何时做。
- day6 回答这些工作花多少钱。
- day7 回答交付成果质量如何。
- day8 则要回答：这些工作到底由谁做，资源怎么分配，团队如何协同，冲突如何化解。

也就是说，今天的本质是：

**把已经确定的范围、进度、成本、质量要求，进一步落实到“谁来做、怎么协作、资源够不够、团队状态如何”这个层面。**

### 4. 今天真正要完成的 5 件事

1. 搭建资源管理与团队管理主线。
2. 掌握角色职责、责任分配矩阵、资源日历、激励理论、冲突管理、资源平衡与资源平滑等高频概念。
3. 做完 30 道选择题。
4. 做 2 道资源/团队案例题。
5. 完成一版“资源管理”或“团队管理”论文提纲。

## 四、今天要掌握的核心知识

## 1. 资源管理主线

今天必须记住的主线是：

1. 规划资源管理
2. 估算活动资源
3. 获取资源
4. 建设团队
5. 管理团队
6. 控制资源

### 1. 这条主线怎么理解

可以把它理解为下面这条链：

- 先明确需要哪些人和物
- 再估算每项工作需要多少资源
- 再把资源真正拉到项目里
- 再通过建设团队和管理团队让资源发挥作用
- 最后在执行中监控资源使用状态并纠偏

### 2. 为什么资源管理经常被低估

因为很多人把资源管理理解成“缺人就要人”。

实际上资源管理还包括：

- 资源结构是否合理
- 职责是否清楚
- 资源冲突是否被协调
- 团队状态是否健康
- 实物资源是否按时可用
- 资源使用是否被监控和调整

## 2. 人力资源与实物资源

### 1. 人力资源

人力资源主要指项目中的人，包括：

- 项目经理
- 需求分析师
- 架构师
- 开发人员
- 测试人员
- 实施工程师
- 运维支持人员
- 外部供应商顾问等

### 2. 实物资源

实物资源主要指项目所需要的设备、场地、网络、环境、工具、测试机、硬件终端等。

### 3. 为什么考试会把二者混着考

因为在信息系统项目里，资源不只是“人”，还可能包括：

- 测试环境
- 联调设备
- 门禁终端
- 网络专线
- 机房窗口

所以做题时要先判断题目说的是“人不够”还是“物不到位”。

## 3. 角色、职责与责任分配矩阵

### 1. 角色和职责为什么重要

项目中最常见的管理问题之一，不是没人做事，而是：

- 大家都以为别人会做
- 出问题后没人负责
- 多部门同时插手，口径不一

### 2. 常见职责分配工具

最常见的是责任分配矩阵，其中高频写法是 RACI：

- R：Responsible，负责执行
- A：Accountable，对结果负责
- C：Consulted，需征询意见
- I：Informed，需被通知

### 3. 用 RACI 时容易犯的错

- 一个任务上 A 过多，导致责任不清
- 只写 R 不写 A，结果没人真正负责到底
- 大量人员都放进 C 和 I，反而让沟通成本失控

### 4. 资源日历

资源日历用于说明：

- 谁在什么时候可用
- 哪些时间不可用
- 哪些岗位是兼职还是全职
- 哪些资源存在节假日、外部窗口、轮班等约束

## 4. 获取资源

### 1. 获取资源的核心问题

获取资源不是简单发邮件要人，而是要解决：

- 人从哪里来
- 资源何时到位
- 是否够用
- 是否具备对应能力
- 外部资源是否能按承诺交付

### 2. 获取资源的常见难点

- 矩阵型组织里，项目经理对人员没有直接行政控制权
- 多项目共享关键专家，存在抢人现象
- 供应商承诺和实际到位不一致
- 关键岗位替补不足

### 3. 项目经理常见动作

- 提前锁定关键岗位
- 与职能经理协调资源窗口
- 明确关键岗位备份方案
- 对外部资源的交付时间和能力做确认

## 5. 建设团队与管理团队

### 1. 建设团队

建设团队更强调：

- 提升能力
- 建立信任
- 形成协作机制
- 让团队从“拼凑的人”变成“能协同的团队”

常见动作：

- 培训
- 结对协作
- 团队规则制定
- 阶段复盘
- 联合评审与共享经验

### 2. 管理团队

管理团队更强调：

- 跟踪绩效
- 处理冲突
- 解决资源障碍
- 激励成员
- 调整分工

也可以理解为：

- 建设团队偏“把团队建起来”
- 管理团队偏“让团队持续有效运转”

## 6. 团队发展阶段

考试中常会考团队发展阶段模型，常见阶段包括：

1. 形成阶段
2. 震荡阶段
3. 规范阶段
4. 发挥阶段
5. 解散阶段

### 1. 各阶段的常见表现

- 形成阶段：成员彼此不熟，更多在观察和试探
- 震荡阶段：观点冲突明显，职责边界和做法容易争论
- 规范阶段：规则逐渐明确，协作开始稳定
- 发挥阶段：团队效率高，成员可以较自主协作
- 解散阶段：项目结束或阶段结束，团队转移或解散

### 2. 高频易错点

- 震荡阶段出现冲突是常见现象，不等于团队失败
- 管理者在不同阶段应采取不同方式，不能一把尺子量到底

## 7. 冲突管理

### 1. 项目冲突常见来源

- 资源稀缺
- 优先级不一致
- 职责边界不清
- 技术路线分歧
- 进度压力过大
- 考核目标不一致
- 多部门协作口径不一致

### 2. 冲突处理方式

常见方式包括：

- 回避
- 缓和
- 妥协
- 强制
- 解决问题

### 3. 怎么快速判断哪种方式更优

- 临时压住局面、争议不大时，可短期回避或缓和
- 资源紧张、需要双方都退一步时，可妥协
- 时间极紧、必须立即决策时，可能会用强制
- 从长期看，最推荐的是解决问题，即找到根因并形成双方可接受方案

### 4. 考试里最爱考的点

- 不是所有冲突都要立刻压掉
- 项目经理不应长期依赖强制
- 真正高质量的做法通常是解决问题，而不是只做表面安抚

## 8. 激励理论与领导方式

### 1. 为什么项目经理必须懂激励

项目团队很多成员并不直接归项目经理行政管理，光靠“命令”往往无效。

项目经理需要通过：

- 目标清晰
- 反馈及时
- 认可与授权
- 发展机会
- 合理考核

来让团队愿意投入。

### 2. 常见激励理论

#### 1. 马斯洛需求层次

从低到高可以理解为：

- 生理
- 安全
- 社交
- 尊重
- 自我实现

#### 2. 赫茨伯格双因素理论

- 保健因素不足会导致不满
- 激励因素到位才更容易提升积极性

#### 3. 麦格雷戈 X 理论与 Y 理论

- X 理论偏向认为员工需要更多控制
- Y 理论偏向认为员工愿意承担责任、可以自我驱动

### 3. 做题时怎么用

考试通常不是考你背理论原句，而是看你能否判断：

- 团队积极性低，问题出在保健因素还是激励因素
- 项目经理是过度控制还是合理授权

## 9. 资源平衡与资源平滑

### 1. 资源平衡

资源平衡强调在资源不足或冲突明显时，通过调整活动安排来解决资源过载问题。

它的特点是：

- 可能影响关键路径
- 可能导致总工期变化
- 目标是先解决资源不可行问题

### 2. 资源平滑

资源平滑强调在不突破既定关键时间约束的前提下，让资源使用更均衡。

它的特点是：

- 通常不希望改变关键路径
- 一般不突破主要进度约束
- 更偏向优化资源曲线，而不是硬解决资源短缺

### 3. 高频考法

- 资源不够且必须可执行，优先想到资源平衡
- 资源总体够，只是波峰波谷太明显，优先想到资源平滑

## 10. 控制资源

控制资源强调的是：

- 跟踪资源实际使用情况
- 识别资源偏差和低效浪费
- 对资源配置进行调整
- 确保实物资源和人力资源按计划支持项目执行

常见动作包括：

- 核查关键岗位到岗情况
- 检查设备和环境是否按时到位
- 调整人力负荷和分工
- 跟踪外部资源履约状态

## 11. 今天最容易混的概念

| 易混概念 | 正确区分 |
| --- | --- |
| 建设团队 vs 管理团队 | 一个偏能力建设和协作形成，一个偏绩效跟踪和冲突处理 |
| 角色 vs 职责 | 一个偏定位，一个偏具体承担的工作和责任 |
| R 和 A | 一个偏执行负责，一个偏结果负责 |
| 人力资源 vs 实物资源 | 一个是人，一个是设备、场地、环境等 |
| 资源平衡 vs 资源平滑 | 一个先解决资源不可行问题，一个先做资源优化 |
| 冲突解决 vs 强制压制 | 一个偏根因解决，一个偏短期命令性处理 |
| 激励 vs 单纯加班 | 激励是机制和心理驱动，不是简单延长工作时间 |

## 八、案例题

### 案例 1：关键资源冲突与排期失衡

#### 1. 案例背景

某智慧园区综合管理平台项目进入详细设计和联调准备阶段后，项目经理发现同一名核心架构师同时被安排支持统一身份认证、停车联动和能耗平台 3 个关键模块。由于该架构师还兼顾另一个项目，本周只能投入 40% 时间。

项目组当前表现为：

- 三个模块负责人都认为自己的任务最紧急。
- 没有形成明确的资源优先级和替代方案。
- 部分设计评审反复延期。
- 团队内部开始互相抱怨，认为项目经理“只会催、不协调”。

#### 2. 问题

1. 该项目至少暴露出哪些资源管理问题。
2. 为什么这不只是“缺一个人”的问题。
3. 站在项目经理角度，给出至少 6 条改进措施。

#### 3. 参考答案要点

可从以下角度作答：

1. 关键资源识别不足，未提前锁定架构师时间窗口。
2. 缺少资源优先级判断、替代方案和备份机制。
3. 多项目共享资源冲突未被及时协调。
4. 资源日历和关键里程碑之间未有效联动。
5. 项目经理应评估关键路径和任务优先级，协调职能经理，重新分配支持顺序。
6. 对关键岗位建立备份和知识共享机制，避免单点依赖。

### 案例 2：团队冲突与职责不清

#### 1. 案例背景

某项目在试运行准备阶段，开发组和实施组围绕“缺陷到底由谁负责”发生长期冲突。开发组认为很多问题是实施环境和配置问题，实施组认为开发交付物本身质量不稳定。项目经理多次临时开会，但没有明确责任分工和闭环规则。

进一步发现：

- 缺少统一的问题分类标准。
- 责任分配长期靠口头约定。
- 团队成员普遍觉得“多做多错，少做少错”。
- 项目经理长期靠压任务维持节奏，缺少正向激励。

#### 2. 问题

1. 该项目主要暴露出哪些团队管理问题。
2. 为什么不能只写“加强沟通”。
3. 项目经理应如何从职责、机制、冲突处理和激励四个维度改进。

#### 3. 参考答案要点

可从以下角度作答：

1. 职责边界不清、缺少责任分配矩阵。
2. 缺少问题分类标准和闭环流程。
3. 项目经理长期依赖强压，团队信任和积极性不足。
4. 应通过责任分配矩阵明确责任人和审批人。
5. 建立问题分级、指派、验证、关闭机制。
6. 对争议问题采用解决问题方式，避免长期强制压制。
7. 通过认可、反馈和阶段复盘改善团队积极性。

- 项目节点紧、任务交叉多，资源冲突明显

- 识别关键岗位和关键实物资源

- 用责任分配矩阵明确角色职责
- 对关键岗位设置备份和共享机制

#### 第三部分：团队建设与团队管理

可写动作：

- 通过培训、规则、复盘和联合评审建设团队
- 跟踪团队绩效和协作状态
- 通过问题分析和机制优化解决冲突
- 结合授权、认可和反馈提升积极性

#### 第四部分：问题、改进与成效

可写内容：

- 出现过哪些问题，例如资源冲突、职责不清、协作效率低、关键专家过载
- 采取了哪些措施，例如重排优先级、协调职能经理、明确责任矩阵、建立备份机制、优化激励方式
- 取得了哪些效果，例如协作效率提升、返工减少、关键任务稳定推进

### 4. 论文可直接复用的表达

- 为提高项目资源配置效率，我在项目初期组织识别关键岗位与关键实物资源，并结合项目里程碑编制资源计划和资源日历。
