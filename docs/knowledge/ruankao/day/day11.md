# 第 11 天：采购管理、合同管理、招投标与法律法规

## 一、今天的目标

第 11 天进入信息系统项目管理师里一个非常容易出现“概念似懂非懂、案例答题却经常失分”的板块：采购管理、合同管理、招投标与法律法规。

这一模块的难点不在于记忆量特别大，而在于它横跨四类题型：

- 综合知识会考采购管理主线、合同类型、招投标流程、合同变更、索赔、知识产权、保密义务、违约责任等高频概念。
- 案例分析经常把采购延误、供应商履约不足、合同边界不清、验收争议、付款节点失控、未按流程招标等问题混在一起，考你能否判断问题本质。
- 论文题虽然未必直接命题为“法律法规”，但在采购管理、合同管理、整体管理、风险管理、干系人管理等主题中，经常需要写出规范采购和合同管控动作。
- 实务表达里，很多考生会把“采购计划”“合同签署”“招标采购”“供方管理”“付款验收”“索赔争议”混成一团，导致答案泛化。

- 能分清合同、变更、索赔、违约、验收之间的边界。
- 能基于 day1 的主项目背景，写出一版“采购管理”或“合同管理”论文提纲。

## 三、今天必须先了解的信息

### 1. 为什么采购管理不是“买东西”

很多考生一看到采购管理，就本能地理解为：

- 买设备
- 买软件
- 选供应商

但考试语境里的采购管理，本质上管理的是：

- 组织是否真的需要外购
- 采购范围如何界定
- 通过什么方式选供方
- 合同如何约定责任、价格、质量、工期、验收和付款
- 履约过程中如何控制偏差、处理变更、索赔和争议

所以采购管理不是“买到了就结束”，而是：

**从外部获取资源或成果的全过程控制。**

### 2. 今天要重点解决的 6 个问题

1. 采购管理主线包括哪些步骤，各自解决什么问题。
2. 合同类型有哪些，风险主要落在哪一方。
3. 招投标的标准逻辑是什么，哪些动作不能乱。
4. 合同变更、索赔、违约、验收分别是什么。
5. 法律法规在考试里通常怎么考，不需要背法条也要抓住什么边界。
6. 论文里怎样把采购与合同写得既规范又不像空话。

### 3. 今天和前几天的关系

- day4 到 day10 主要在学项目内部管理机制。
- day11 开始，重点转向组织与外部供方的关系管理。

也就是说，前面更多是在管“自己人和自己事”，今天则是在管：

**哪些工作自己做，哪些工作交给外部做，以及如何确保外部也按项目目标交付。**

### 4. 今天真正要完成的 5 件事

## 四、今天要掌握的核心知识

## 1. 采购管理主线

今天必须记住的主线是：

1. 规划采购管理
2. 实施采购
3. 控制采购

### 1. 这条主线怎么理解

可以把它理解为下面这条链：

- 先决定买不买、买什么、怎么买、怎么管
- 再通过询价、招标、谈判等方式选定合适供方
- 再在履约期间跟踪交付、验收、付款、变更和争议

### 2. 考试最容易考混的点

- 把“需求分析”和“采购规划”混在一起
- 把“签完合同”当成采购管理结束
- 把“控制采购”和“变更控制”“验收管理”边界混在一起

## 2. 采购决定：自制还是外购

### 1. 为什么要先做自制外购分析

采购管理首先不是问“买谁家的”，而是问：

- 这项工作是不是应该外购
- 组织内部有没有能力完成
- 外购是否更省时、省钱、降低风险

### 2. 常见判断维度

- 成本
- 工期
- 专业能力
- 资源可用性
- 保密要求
- 质量可控性
- 供应市场成熟度

### 3. 高频陷阱

- 不是“内部忙不过来”就一定要外购
- 不是“外包了”就不再对质量和风险负责

## 3. 合同类型

### 1. 总价合同

更强调：

- 范围相对明确
- 价格整体固定或大体固定
- 买方成本可预测性较强

适合：

- 需求较清晰
- 范围边界较稳定
- 交付成果可明确描述

### 2. 成本补偿合同

更强调：

- 先补偿合理成本，再加费用或激励
- 范围不够清晰或不确定性较高时更常见

适合：

- 技术复杂度高
- 工作量不易准确估算
- 需要较强柔性

### 3. 工料合同

更强调：

- 按人工单价、材料或工时单价结算
- 常用于边做边细化、阶段性投入的场景

适合：

- 范围局部明确但整体工作量波动较大
- 短期支持、专家服务、驻场服务

### 4. 合同风险如何理解

- 总价合同下，卖方通常承担更多成本超支风险
- 成本补偿合同下，买方通常承担更多成本波动风险
- 工料合同的关键风险在于总量失控和过程监督不足

### 5. 高频易错点

- 不能简单理解为“总价合同最好”
- 合同类型没有绝对优劣，只有是否适配项目不确定性

## 4. 招投标与供方选择

### 1. 为什么招投标是采购管理高频点

因为考试不仅考“懂不懂流程”，还考你是否明白：

- 采购文件要清晰
- 评审标准要前置明确
- 选择供方要留痕、客观、合规

### 2. 常见流程理解

可以先按下面顺序理解：

1. 明确采购需求和边界
2. 编制采购文件
3. 发布采购信息或邀请供应商
4. 获取投标或报价
5. 组织评审与澄清
6. 选择中标或成交对象
7. 签订合同
8. 履约、验收与付款

### 3. 常见供方选择方法

- 综合评分
- 最低报价法
- 独立估算
- 专家判断
- 谈判

### 4. 高频陷阱

- 评审标准不能到评标时才临时改
- 不能只看价格，不看能力、交付、服务、风险
- 招采过程和合同条款要前后衔接，不能前松后紧

## 5. 合同管理与履约控制

### 1. 控制采购阶段通常关注什么

- 供方是否按合同要求交付
- 范围、质量、进度、费用是否偏离约定
- 验收资料是否齐全
- 付款节点是否满足条件
- 是否存在索赔、变更或争议

### 2. 合同管理的核心不是“存档合同”

而是要做到：

- 按合同执行
- 出现偏差及时识别
- 所有争议有依据、有记录、有处理流程

### 3. 高频考法

- 供应商延期交付怎么办
- 验收标准不清导致争议怎么办
- 口头承诺和合同文本冲突时怎么办
- 付款条件没达成能否付款

## 6. 合同变更、索赔与违约

### 1. 合同变更

合同变更强调：

- 对合同范围、工期、费用、技术要求、交付方式等作正式调整
- 必须按约定流程审批和留痕

### 2. 索赔

索赔强调：

- 一方因对方责任或合同约定情形遭受损失，请求工期、费用等补偿

### 3. 违约

违约强调：

- 一方未按合同义务履行或履行不符合约定

### 4. 快速区分法

- 合同内容变了，是变更
- 因对方责任要求补偿，是索赔
- 没按合同履行，是违约

### 5. 高频易错点

- 不是所有延期都能索赔
- 不是所有新增工作都能直接做，很多必须先走变更
- 违约认定要看合同约定和履约事实，不能拍脑袋

## 7. 验收、付款与争议处理

### 1. 验收关注什么

- 交付物是否符合范围和技术要求
- 文档是否齐全
- 测试和试运行结果是否达标
- 是否达到约定的验收条件

### 2. 付款关注什么

- 是否满足合同约定的付款触发条件
- 验收节点、发票、证明材料是否齐备
- 是否存在未关闭问题或争议

### 3. 争议处理关注什么

- 先看合同约定
- 看履约记录和证据
- 看是否已做留痕和正式通知

### 4. 高频陷阱

- 验收未达标不能因为赶进度就强行通过
- 口头沟通不能替代正式确认
- 付款不是“关系好了就能付”，而要以合同条件为依据

## 8. 法律法规与知识产权高频边界

### 1. 考试里法律法规通常怎么考

一般不会要求你逐条背法条，而是考：

- 是否依法合规采购
- 是否尊重合同效力与约定义务
- 是否重视知识产权、保密义务和成果归属
- 是否能识别无效或高风险管理动作

### 2. 知识产权常见考点

- 软件著作权
- 技术文档和交付成果归属
- 未经授权不得擅自复制、传播、使用受保护成果

### 3. 保密与合规常见考点

- 涉及敏感数据、源代码、设计资料时要有保密约束
- 供应商参与不等于可以无限制接触全部资料

### 4. 职业道德与采购合规

高频理解是：

- 公平
- 公正
- 透明
- 留痕
- 回避利益冲突

## 9. 采购管理论文怎么写才像项目经理

### 1. 论文常见空话风险

很多人会写：

- 我重视采购管理
- 我严格按照流程办事
- 我加强供应商管理

这些都太空。

### 2. 更好的写法

应该写出：

- 采购对象是什么
- 为什么要外购
- 如何确定采购边界与技术要求
- 如何选择供应商
- 如何设置合同关键条款
- 如何管控交付、验收、付款和变更
- 最终效果如何

### 3. 推荐表达链条

可以按下面链条展开：

需求分析 -> 自制外购判断 -> 编制采购文件 -> 选择供应商 -> 签约 -> 履约跟踪 -> 验收付款 -> 复盘改进

## 10. 今天最容易混的概念

| 易混概念 | 正确区分 |
| --- | --- |
| 采购管理 vs 合同管理 | 一个管外购全过程，一个更聚焦合同履约与约束 |
| 合同变更 vs 索赔 | 一个是改约定，一个是要补偿 |
| 验收 vs 付款 | 一个确认交付符合要求，一个是依据条件支付 |
| 总价合同 vs 成本补偿合同 | 一个价格相对固定，一个买方承担更多成本波动 |
| 招标评审 vs 合同谈判 | 一个侧重选择供方，一个侧重明确签约条款 |
| 口头承诺 vs 正式合同文件 | 一个参考性弱，一个具有正式约束和证据作用 |

## 八、案例题

### 案例 1：供应商延期与验收争议

某市智慧园区综合管理平台建设项目采购了一批视频接入网关设备和配套实施服务。合同约定设备到货后 10 天内完成安装联调，联调通过并提交测试报告、安装文档后支付第二笔款项。

实际执行中，供应商比计划晚到货 12 天，项目组为了赶节点，要求现场实施团队先行进场。由于设备固件版本与合同技术规格不完全一致，联调反复失败。供应商口头承诺“先把系统跑起来，资料后补”，项目组内部也有人主张“先验收、先付款，不然后面更难推进”。

问题：

1. 该场景至少暴露出哪 4 个采购或合同管理问题。
2. 作为项目经理，应如何处理当前局面。
3. 后续如何在采购文件、合同条款和履约控制中避免类似问题。

参考答题方向：

- 识别问题：延期交付、设备型号或版本不符、验收条件未满足、口头承诺替代正式文件、付款与验收边界不清。
- 处理动作：核对合同与技术规格、正式记录偏差、暂停不满足条件的验收付款、要求供应商提交整改计划、必要时按合同启动违约或索赔处理。
- 预防动作：明确技术规格、到货验收要求、联调标准、文档交付要求、付款触发条件、偏差处理机制。

### 案例 2：需求变化引发的合同变更与索赔争议

某园区综合平台项目原合同只约定建设统一门户、工单系统和基础报表。项目推进到中期时，甲方新增了移动端审批、领导驾驶舱和第三方短信平台对接，并要求仍按原里程碑完成上线。供应商提出新增工作量较大，要求追加费用和延长工期；甲方代表则认为“都是一个平台里的功能，应该算在原合同里”。

问题：

1. 该争议的核心矛盾是什么。
2. 项目经理应如何组织合同变更评估。
3. 如果双方未提前明确范围边界，后续论文中应怎样总结经验教训。

参考答题方向：

- 核心矛盾：范围边界不清、原合同约定不足、需求新增与原约定关系不明。
- 评估重点：新增功能是否超出原范围、对工期成本质量资源的影响、是否需要调整合同金额和里程碑、是否需要补充验收标准。
- 经验教训：采购文件和合同条款必须把范围边界、交付清单、变更流程写清楚。
